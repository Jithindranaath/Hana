Created during Phase 2.2 (`WORKFLOW.md`). Two demo wallets, seeded with distinct, explicitly
disclosed histories via `HanaCreditAttestor.seedHistory` (owner-only — see the contract's
`README.md` for why this isn't hidden), each with one real `snapshot()` tx on Sepolia.

`HanaCreditAttestor` deployed and **verified** at:
**[`0x89D15677c532eccDf5c8eBff69e38DB13ce966C5`](https://sepolia.etherscan.io/address/0x89D15677c532eccDf5c8eBff69e38DB13ce966C5#code)**
(Sepolia, deployer `0xccEF39b7e2081b9c814DBbf0e51D450DdaBB64a2`).

Demo wallet keys live in `hana-ctc-attestor/.demo-wallets.json` (gitignored, not reproduced here)
— generated by `scripts/seed.ts`, funded with a small amount of Sepolia ETH from the deployer
wallet so each could sign its own `snapshot()`.

(`0x32c784848B052dFe1a2480A4fdC3eAcad7781940`) on CC3 — no mocks, no local Hardhat, the actual

once built, or can be run the same way (`bridge/importer/submit_query.ts` in the Phase 1 spike
scratch clone) any time before that.

## Phase 5: worker proven end-to-end (including resume-after-kill)

With `@hana/worker` running against the live deployments (`WORKER_START_BLOCK=11639999`):

1. **Cold-start backfill**: worker found both untouched-by-worker demo snapshots on boot. The
   "excellent" one (nonce 1) had already been imported manually (Phase 4 test) — its static-call
   caught `"asc: replay"` and it resolved to `CONFIRMED` without spending gas. The "thin" one
   (nonce 1) was genuinely new — imported for real, tx
   `0xc2b42fdd944437f0986237bbfda7587aacd21e0beb82d3d44ff5fdfc080d292f`.
2. **Live pickup**: fired a fresh `snapshot()` from the "excellent" wallet (nonce → 2, tx
   `0x87372eb2d5fc828c3b7321d425f59187295d6a5d638d9ca4d95be1d61a6d766d`, block 11640734) while the
   worker was running. Picked up within one poll interval, entered `ATTEST_WAIT`.
3. **Kill mid-`ATTEST_WAIT` + restart**: killed the worker process while `GET /status/...` still
   showed `ATTEST_WAIT`. On restart, it logged `resuming 1 pending job(s)` and re-entered the
   pipeline from scratch (safe — every step is idempotent, see `hana-ctc-worker/README.md`).
4. **Resolved to `CONFIRMED`** once attested, with a real (non-replay) import tx:
   `0xc38bf69c7112b3ff26212e5899d2f4acee966c9b171378e9e3b33b9affdfb081`. `registry.importNonceOf(1,
   subject)` confirmed on-chain at `2` afterward — no double-submit, no duplicate write.

This is the WORKFLOW.md 5.1 acceptance check, run for real rather than simulated.

  `.demo-wallets.json`) but fires a **new** `snapshot()` each time, bumping `snapshotNonce`. If you
  need the exact fixtures above reproduced later (e.g. for the worker's cold-start test), use the
  tx hashes on this page rather than re-running the script.
